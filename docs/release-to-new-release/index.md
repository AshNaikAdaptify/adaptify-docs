# Release to New Release

Use this path when a published product needs changes to its forms or rates. You update the product once in the Project Workbench. Then you file it state by state in Filing Manager. Each state's approval becomes that state's new release in the Product Vault.

## Before you start

- The product is published in each state you want to change, for example with a **Baseline** release. See [Review and publish](../product-vault/review-and-publish.md).
- Your organization's filing workflow and owners are set up. If you're not sure, ask your organization admin.

## The path

Product Vault (current release) → Workbench project → one filing per state in [Filing Manager](../filing-manager/index.md) → Product Vault (new release)

1. [Update your product in Workbench](update-in-workbench.md): change forms and rates in one project.
2. [Create filings from your project](create-filings.md): complete the project as **Admitted** to get one filing per state.
3. Add documents and supporting materials to each filing, as the state requires.
4. [File with the state and record the submission](submit-to-state.md): download the ZIP, file in SERFF, and record it.
5. [Track objections and responses](handle-objections.md): log the state's objection and your response.
6. [Record approval and archive to a new release](approve-and-archive.md): mark the filing **Approved** and create the new release.
7. [Check the new release in the Product Vault](check-new-release.md): confirm each state shows its new release as current.

!!! note "Each state moves on its own"
    Each state's filing is submitted, approved and archived separately. One state can reach its new release while another is still answering an objection.
