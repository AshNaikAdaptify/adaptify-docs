# Start a product update

Start a product update when a published product needs changes to its forms, rates or rules. One project can cover several states.

## Before you start

- The product is published in each state you want to change. See [Review and publish](../../product-vault/review-and-publish.md).
- Your organization's document storage is set up. Form work needs it. `TODO verify` who sets it up.

## Steps

1. In **Workbench**, choose **+ New project**, then **Product update**.
2. **Setup:** under **Project type**, choose **Forms**, **Rates** or **Rules**, then choose **Next**. Choose more than one to create a combined project with a child project for each type.
3. **Configuration:** choose the **Product** and the **Jurisdictions**, for example Personal Auto and Alabama. Then choose **Next**.
4. **Finalize:** enter the **Project title** and a short **Project description**, for example "Personal Auto – Fall 2026 forms and rates update".
5. Choose the **Workflow**, for example **Product Update**, and pick a **Due date** from the calendar.
6. You're listed under **Default members**. Add teammates under **Additional members** if you need them.
7. Choose **Create**.

A single project opens at its first phase, **Select**. A combined project opens on its **Projects** tab, listing a child project for each type. Next, add your changes: [Update forms](../update-forms.md) or [Update rates](../update-rates.md).

!!! note "Good to know"
    - The states you choose decide which Vault files the update can use. The states that get filed are worked out later from what you change.
    - Keep the description short. Only the first 100 characters are kept.
